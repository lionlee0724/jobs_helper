# BOSS 求职副驾驶（Chrome 扩展）

本地 Chrome MV3 扩展：在 BOSS 直聘页面上，用 LLM 判断职位是否合适，按你配置的限速自动开聊（默认招呼），并跟进聊天（识别发简历 / LLM 话术）。数据存本机 IndexedDB，可统计与导出。

## 风险声明

- 可能违反 BOSS 用户协议，存在限流、封号风险；请自担后果，建议节制使用、专用账号。
- 「后台运行」= **Chrome 进程内**、不依赖当前前台标签；**完全退出 Chrome 即停止**。
- 关闭扩展持有的 BOSS 工作标签会暂停任务。

## 加载扩展

1. `npm run build`
2. Chrome 打开 `chrome://extensions`
3. 开启「开发者模式」
4. 「加载已解压的扩展程序」→ 选择本仓库的 **`dist`** 目录
5. 点击扩展图标打开 **侧栏**

## 使用步骤

1. 浏览器登录 [BOSS 直聘](https://www.zhipin.com)
2. 侧栏配置 **LLM**（OpenAI 兼容：baseURL / apiKey / model）
3. 选 **风控档位**（默认保守）预填限速建议，**填写并保存日开聊上限**（必填），打开「启用自动执行」
4. 「从 BOSS 简历页同步」或手填简历摘要
5. （可选）设硬否规则：期望城市 / 最低薪资 / 排除词 / 年限差距
6. 点 **开始**（职位线默认开启环 B：与开聊交错自动跟进；可在策略关闭）

调度器会：

- 确保后台 worker 标签在 zhipin
- 取职位 → 硬否规则 → LLM 分档评分 → 综合分达阈值才限速「立即沟通」
- 对已开聊会话：按意图分级处理（见下）

## 风控机制

三档预设，默认**保守**：

| 档位 | 日上限 | 小时上限 | 时段 | 拟真 |
|---|---|---|---|---|
| 保守 | 30 | 6 | 9-20 点（不再锁定周末） | 强 |
| 平衡 | 60 | 12 | 8-22 点 | 中 |
| 激进 | 150 | 30 | 全天 | 关 |

除限速外还做了：

- **节奏形状**：对数偏置分布 + 随机长休，避免均匀随机这种可统计识别的特征
- **行为拟真**：阅读停留、分段滚动、逐字输入、发送前停顿
- **小时配额**：防止日配额在一小时内集中消耗
- **指数退避**：异常分级（captcha / auth_lost / rate_hint / action_failed），连续异常逐次放大冷却，**冷却期内阻断重新开始**（刚撞验证码就重试是最危险的行为）

## 匹配机制

1. **硬否规则**（确定性，先于 LLM）：城市 / 薪资下限 / 年限差距 / 排除词
   - 原则：**证据不足不拒绝**。薪资读不到、JD 未写年限要求时一律放行，避免因抓取缺陷误杀
2. **LLM 分档评分** 0-100（strong / moderate / weak / reject）
3. **综合分** = LLM × 0.75 + 关键词 × 0.25，≥「开聊最低分」（默认 50）才投


关键词单通道得分**封顶 60**：字面命中不等于方向匹配，不能凭关键词达到高档。

## 自动回复分级

| 意图 | 处置 |
|---|---|
| 请发简历 | 自动点平台「发简历」 |
| 到岗时间 / 工作地点 / 一般寒暄 | LLM 自动回复 |
| **薪资谈判** | 转人工（会形成事实承诺） |
| **面试邀约** | 转人工（涉及时间承诺） |
| **索要联系方式** | 转人工（隐私） |
| 拒绝 / 系统消息 | 不回，标结束 |

另有**出站护栏**：发送前扫描手机号/邮箱/微信号，命中则拦截并转人工—— 提示词约束不是可靠保证，需要最后一道确定性防线。

边界可在侧栏调：分级（默认）/ 仅发简历 / 全自动。

## 消息队列与处理节奏

**会话从哪来**

| 来源 | 写入时机 | 职位上下文 |
|---|---|---|
| `self` | 本扩展开聊成功后自动写入 | 有（JD、公司、薪资）|
| `imported` | 你点「导入现有会话」后写入 | 无，回复更保守 |

历史会话、手动开聊的会话、重装后丢失的会话，都靠**导入**找回。
导入是显式操作：启动处理循环不会静默把消息列表里的陌生会话拉进来。

**跟进 owner（默认）**：消息助手（侧栏「消息」Tab / 消息页浮层）。  
职位线内环 B 跟进**默认关闭**；仅在策略中勾选「职位线内跟进」时，与开聊交替。

**处理顺序**：有未读 → 最近扫到未读的 → 久未跟进的。未读从消息列表徐标读取，
处理完立即清除，避免同一会话卡在队首反复被取出。

**三个入口**

| 入口 | 行为 |
|---|---|
| 处理到队列清空 | 逐条跑直到清空，受限速/日上限/活跃时段约束，侧栏实时显示已完成与剩余，可随时停 |
| 只处理一批 | 一次最多 `batchSize` 条（默认 5）|
| 职位线环 B（可选） | 勾选后每 tick 与投递交替 1 条 |

「处理到清空」用 **alarm 驱动的持久化状态机**，不是长循环：
MV3 的 Service Worker 会在空闲时被回收，跨越数分钟、中间还要按限速等待的循环必然被打断。
每次只处理一条，下次唤醒时间写进 alarm，SW 被回收也能继续。

## 选择器自检

页面改版导致「点不动」「抳不到」时，先跑侧栏的 **选择器自检**（在对应页面上点），会下载一份 JSON，包含：

- 每组选择器的命中数与命中到的元素
- 职位卡是否带 `job_detail` 链接（自动流程的硬前提）
- 薪资字体混淆的解码与标定结果
- 按文案反查的真实候选元素及建议选择器

不要直接猜选择器—— 本仓库早期的 `.tmp-*.html` 快照全是反爬拦截页，选择器曾长期未经验证。

## 薪资字体混淆

BOSS 用 `kanzhun-mix` 字体把薪资数字映射到 Unicode 私有区（U+E031–U+E03A），
`textContent` 只能读到 `-K`。处理方式：

1. **字形标定**（主）：canvas 渲染私有区字符与 0-9 比对位图签名，抗字体映射轮换
2. **静态基准**（备）：标定失败时回退
3. **形状校验**：min>max、>999K、薪月数异常一律拒绝

任何一步存疑就当**薪资缺失**，宁缺勿错：错误的薪资会直接污染硬否规则。

## 模块结构

```text
extension/
  background/   # 编排、LLM、alarm（唯一策略 owner）
  content/      # 仅 DOM 适配 + 行为拟真执行
    adapter/boss/
      selectors.ts        # 选择器（改版优先改这里）
      probe.ts            # 实页选择器自检探针
      obfuscated-text.ts  # 私有区字体解码
      font-calibration.ts # canvas 字形标定
  domain/       # 纯函数：policy / risk / intent / match / match-rules
  data/         # chrome.storage + IndexedDB(Dexie)
  ui/sidepanel/ # 配置与统计
  shared/       # 类型与协议
```

依赖方向：`content` 不持有策略，只执行 SW 下发的参数；`domain` 无 DOM / 无 chrome.*。

页面改版时优先改：`extension/content/adapter/boss/selectors.ts`
